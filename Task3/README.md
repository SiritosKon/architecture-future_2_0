## Обоснование этапов (зачем каждый с точки зрения бизнеса)

- **Фаза 0 — Фундамент.** Без согласованных границ доменов и облачной основы любые изменения снова осядут в DWH. Этап даёт предсказуемость и убирает технический/лицензионный риск старого SQL Server. *Влияние:* снижение рисков, база для скорости и масштабирования.
- **Фаза 1 — Платформа и приём.** Замена ESB на Kafka/CDC и появление lakehouse убирают узкое место интеграций и часовые трансформации. Первый data product (Клиника) доказывает подход на реальных данных. *Влияние:* скорость решений (быстрая отчётность), снижение зависимости от DWH.
- **Фаза 2 — Портал (MVP).** Семантический слой + self-service BI закрывают главную цель — витрину данных; IAM и изоляция медданных делают это безопасным. *Влияние:* прямая ценность для бизнеса и комплаенс; качество фин-сервисов (финтех как data product).
- **Фаза 3 — Домены и масштаб.** Независимые домены и каркас для партнёров дают масштабирование без роста логики в хранилище; вывод легаси снижает стоимость поддержки. *Влияние:* time-to-market, масштабируемость, снижение затрат.

Последовательность отражает критичный путь из приоритизации Task 1: сначала убрать корневую зависимость от DWH и заложить безопасность, затем дать быструю отчётность и независимость доменам. Облачная инфраструктура фазы 0 детализирована в Task 4.
